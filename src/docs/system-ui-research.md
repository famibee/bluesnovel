## 0. 前提：分家テンプレのUI実装の土台

`tmp_blues/doc/prj/` を実物として読んだ結果。

| 領域 | 現状 |

### 効いてくる制約：任意位置ジャンプはできない

エンジンの位置移動は **しおりからの演じ直し** が前提。`PageLog` に積まれた **訪問済み停止点へは安全に飛べる**
（`[page to=load]` の仕組み）が、**一度も通っていないシナリオ位置へは変数状態が未定義になり飛べない**。
→ 「シナリオ全文検索して任意地点へジャンプ」は原理的に重い。訪問済みページへのジャンプで代替する。

## 2. 実装対象の詳細

### 3. ボイスカット ●●

**現状**：手動クリック時、ボイスは止まらず次行へ継続。次行に `[voice fn=]` があれば置き換わるので
「未ボイス行では継続」は実質デフォルト動作。差が出るのは *次行が無声のとき* だけ。

**設定変数（英語ワードで持つ）**：

```
sys:sn.sound.voice_cut = 'continue' | 'cut'
```

| 値 | 意味 | 設定画面の表示（例） |
|---|---|---|
| `'continue'`（既定） | クリックで進んでもボイス継続。次行が有声なら自然に置換される | ボイス継続 |
| `'cut'` | クリックで進んだ時点でボイス停止 | クリックでボイスを止める |

- 将来 3値目が要るなら `'cut-read-only'`（既読行のみカット）等を足す余地を残す。数値は使わない。

**実装**：
1. `theme/ext_voice.sn` か `setting.sn` で `sys:sn.sound.voice_cut` の既定を `'continue'` に初期化
2. `main.sn` の `lr` マクロ：`[ws...][wq][l]` の `[l]` 直後に
   `[voice cond="sys:sn.sound.voice_cut == 'cut'"]`（fn省略＝停止）を1行
3. `_config.htm` にラジオ/セレクト、`_config.sn` に `chkChDoWait`（`_config.sn:261-264`）と同型のハンドラ6行
   ＋ `*val2ctrl` に1行、`dicUI` に多言語ラベル

**難易度：小〜中**（エンジン改修なし。全分家が継承する標準マクロ `lr` を触るので慎重に）。
**有用性：高**。有声作品では事実上必須。桜テンプレ自体は無声なので価値が出るのは有声分家。

### 2b. ダイアログ「次から確認しない」 ▲

**現状**：`sub.sn` の `sys_resume_load` に既に `autoResume` 変数があり true ならレジューム確認をスキップ。
汎用化されていないだけ。

**実装**：
- `ask_ync` マクロ（`_yesno.sn`）に `%remember_key` を追加 → `sys:sn.dontAsk.<key>` が立っていれば
  即 `[return]`（`_yesno='y'` 相当を返す）
- `_yesno.htm` に「今後表示しない」チェックボックス1個。OK時にキーを保存
- `_config.htm` に「確認ダイアログの表示設定をリセット」ボタン（`sys:sn.dontAsk.*` を消す）
- まずは「レジューム確認を常にスキップ」チェックを設定画面へ出すだけでも可

**難易度：小**（マクロ＋フレームのみ）。
**有用性：中**。低コストのQoL。

### 4. 便利セーブ ●

**現状**：クイックセーブ/ロード（S/L＋メニュー）実装済み ＝「ダイレクトセーブ」は概ね達成。

**不足（ゆずソフト比）**：
- ① クイック枠が1つで、上書きし続ける（直近を潰す）
- ② セーブボタンにマウスを乗せるとスロット一覧がにゅっと出る

**実装**：
- ①：`_archive.sn *quick_save` の保存先スロットを `(n % k) + 1` でローテーション（`k` は 3〜5）。
  ロードは最新枠。**小**
- ②：`mes_sysmenu` 上にホバー展開の小フレーム or ボタン群。サムネは `[snapshot]` 系
  （`SysBase.capturePage` / DOM→SVG。`ScriptMng` の `#snapshot`）が既にあるので流用可。**中**

**難易度：小〜中**。
**有用性：中〜高**。① だけでも「直近を潰さないクイックセーブ」で実利大。② は演出寄り。

### 8. 非アクティブ時ホイール進行 ●

**現状**：`Stage.tsx:402-408` がステージ div に `wheel` リスナ
（`deltaY<0`→`next()` / それ以外→`prev()`、`{passive:false}`＋`preventDefault()`）。
`wheel` イベントはフォーカス不要で、カーソル直下のウィンドウへ配送されるのが一般的（macOS/Windows とも）
＝ **すでに動く可能性が高い**。

**実装**：
1. まず app 版（electron）で実機確認：別ウィンドウにフォーカスがある状態で、ゲーム画面上のホイールで進むか
2. 動かない場合のみ (a) リスナを `window`/`document` へ移す (b) `BrowserWindow` の設定を確認

**難易度：小**（ほぼ検証）。
**有用性：中**。マルチモニタ運用で効く。

### 5. バックログ→ページジャンプ ▲（シナリオ検索の代替も兼ねる）

**現状**：
- `_log.htm` に行ボタン（`<button>${d.i+1}</button>`）＋右サイド目次が **既にある**（クリックでスクロール）
- `PageLog` が停止点ごとのしおり（変数＋ページ＋位置）を保持
- `[page to=load]`＝「見ているページから再開、後続は切り捨て」が動く
- **目次（`Log`）と `PageLog` は同じ停止点で積まれるのでインデックスが揃う**
  （`Log.pagebreak()` と `PageLog.push()` がどちらも改ページ時）

**実装**：
1. エンジン：`[page]` に数値シークを追加（`PageLog.move()` に分岐数行、`A_PAGE_TO` に相当する
   `place=N` 経路。`ScriptMng` の `[page]` 引数解析に `place` を通す）
2. フレーム：`_log.htm` の行ボタンから `[event key='dom=log:#jumpN']` 発火 →
   `_log.sn` で `[page place=N]`（`const.sn.log.json` の並びと `PageLog` の並びが一致する前提）

**難易度：中**（エンジン小改修＋フレーム配線）。
**有用性：中**。文献優先度▲に同意。**「飛んだら現在位置に戻れない」**（`to=load` が後続を切る）という
セマンティクスの弱さは本質的で、商業作も警告付き/戻れない仕様が多い。
シナリオ検索（旧#7）はこのジャンプ＋バックログの目視で実用上足りると判断し、専用の全文検索は入れない。

### 6. バックログ→小窓プレビュー ●

「バックログの行にマウスを乗せると、その場面の背景/立ち絵/CGが小窓で出る」（文献で9ブランド）。

**方針（スナップショット画像を溜めない）**：
- 停止点ごとに **軽量なシーン状態**（背景/前景レイヤの論理名・座標・スケール・フィルタ
  ≒ `record_place`（`sub.sn` で `[record_place layer=&dsp_lays]`）が保存へ積む情報）を
  `PageLog` エントリ（or `Log` エントリの `[rec_ch]` 属性）に同梱する
- ホバー時、その状態から **React コンポーネント（`GrpLayer` 等）を縮小レンダリングして小窓表示**。
  画像 data-URI を最大64ページぶん保存する方式（セーブ肥大＋撮影コスト大）は採らない

**エンジン/構成の追加**：
1. 停止点でのシーン状態記録（`record_place` 近傍を流用）と、その状態をバックログ側へ渡す口
2. **現バックログは iframe（`_log.htm`）なので、iframe 内では立ち絵 React コンポーネントを描けない**。
   小窓プレビューを React で描くなら、バックログをネイティブ React 画面へ寄せる（iframe をやめる）
   検討が要る。あるいは小窓をエンジン側のレイヤとして本体ドキュメントに出し、iframe からは
   ホバー通知だけを送る

**難易度：中〜大**（記録機構＋バックログのネイティブ化 or iframe↔React 連携）。
**有用性：中**。縦書き文芸系の桜テンプレでは立ち絵より背景差分の想起に効く。

## 4. テスト方針（フェーズ1）

**決定（2026-09-07）**：フェーズ1では自動テストは作らない。実装時の手動確認のみとする。
以下は「もし自動化するなら」の下調べ（将来フェーズや回帰が必要になったとき用に残す）。

### 実装時の手動確認項目

- **#3**：設定でボイスカット=ON にし、有声行→無声行へクリックで進めてボイスが切れること。
  =継続 で切れないこと。次行が有声なら（どちらの設定でも）差し替わること。設定画面の値が
  再入場で保持されていること。
- **#2b**：`ask_ync` で「今後表示しない」にチェック→OK。以後そのダイアログが出ないこと。
  設定画面のリセットで再び出ること。レジューム確認の常時スキップも設定画面から効くこと。
- **#4①**：クイックセーブを k+1 回して、スロットが 1→…→k→1 と回り最古だけ上書きされること。
  クイックロードが最新枠を読むこと。
- **#8**：app 版で別ウィンドウにフォーカスを移し、ゲーム画面上でホイール回転 → 進む/戻る。
  mac・Windows 両方で確認。

### 基盤

bluesnovel には2層あり、そのまま使える：

- **ユニット（`bun test` / `test/*.test.ts`）**：`new ScriptEngine('t1', snソース).step()` が型付きアクション列
  （`playSnd` / `stopSnd` / フレーム表示 / `chgStr` …）を返す。ブラウザ不要・高速。
  `sys:`/`save:` 変数、タグ・マクロ・イベント・`cond=` の分岐まで見られる。
- **E2E（`playwright test -c test/e2e` / `*.e2e.ts` ＋ `test/e2e/app/prj_*` フィクスチャ）**：
  本物の iframe・Web Audio・DOM。`vite` dev サーバは Playwright が起動/終了（`playwright.config.ts`、ポート5199）。

### ネック：フェーズ1はすべてテンプレ側のコード

`doc/prj/` のマクロ（`lr` / `ask_ync`）・フレームHTML・`_archive.sn` が対象で、エンジンのテストスイートは
自動では拾わない。→ `test/e2e/app/prj_<name>/` に **該当マクロを載せた最小フィクスチャ**（`.sn` ＋ 必要な `frames/`）を
足し、それに対して `test/*.test.ts`（ユニット）／`test/e2e/*.e2e.ts`（E2E）を書く。
最小フィクスチャに macro 定義をインラインすると本物のテンプレとdriftしうるので、
テンプレの当該マクロをコピーして載せるか、テンプレ本体を指す。
